2. Observation:

During the CPU stress test, the stress_test.py process used
approximately 95.4% CPU according to htop.

The Codespace provides 2 logical CPUs. However, the Python stress
test did not fully utilize both logical CPUs at 100% simultaneously.

At the time of observation, htop showed approximately:

CPU 0: 38.7%
CPU 1: 93.3%

The python stress_test.py process itself used approximately 95.4%
CPU. This means the CPU-bound Python program was using approximately
one logical CPU worth of processing instead of fully utilizing all
available CPU cores at the same time.


3. Analysis:

Knowing the memory limit and the number of CPU cores is important
before training a Machine Learning model on a large dataset such as
500,000 images.

RAM determines how much data can be loaded into memory at one time.
If the dataset or training batches require more memory than the
system has available, the program may become very slow or fail due
to insufficient memory. Therefore, knowing the available RAM helps
us choose an appropriate batch size and data-loading strategy.

The number of CPU cores is also important because the CPU is used
for tasks such as loading images, preprocessing data, image
augmentation, and other computations. Knowing the available CPU
resources helps us decide how much parallel processing the system
can handle efficiently.

Therefore, checking both RAM and CPU resources before running a
large Machine Learning workload helps prevent resource exhaustion
and allows the program to use the operating system resources more
efficiently.
